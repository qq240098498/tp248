# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、盯温度记录、算超限与断链、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5248（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期的探头数、批次总数与各状态条数、温度记录条数与人工记录数、**人工更正条数与占比提醒探头数**、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、最高与平均 MKT、按冷库一行给出探头与批次数。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数、**更正条数与更正占比**），都带增改删。
- **批次**：批次清单（批次号、品名、规格、件数、所在冷库、入库时刻、状态、温度记录条数、最长超限、累计超限、MKT、断链数、**更正条数**、放行情况），行内展开逐条温度记录（同一时刻的原始值、更正后值、最终采用值并排，带「更正」「历史」入口）、超限段、断链缺口、放行判定四项、**本批次更正留痕**与放行单，并提供「放行」「拒收」入口。
- **温度记录**：记录清单（批次、探头、时刻、**原始值、更正后值、最终采用值并排**、来源、登记人、是否超限），支持按批次、探头、来源、是否已更正、时间筛选，单条新增、删除与**人工更正（登记改前值、改后值、更正人、更正时刻、依据；原始记录留痕不动）**。
- **更正台账**：① 页面顶部可直接改「更正占比提醒阈值」，「应用」只在本页生效、「存为默认」写入设置，占比达到阈值的探头单独高亮提醒；② 按探头汇总（采集时刻数、更正条数、被更正时刻数、更正占比）；③ 按批次汇总（同上口径，并给当前放行判定）；④ 同一探头同一时刻被反复更正（含改了又改回去）的时刻清单，行内按更正序号排出完整历史；⑤ 更正流水（序号、批次、探头、读数时刻、改前值、改后值、原始值、更正人、更正时刻、依据，存量补登与改回原值分别标出）。登记更正后弹窗给出受影响批次放行判定的改前/改后逐项对照。
- **放行台账**：放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、断链数与依据）。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **超限段**：按时刻顺序逐条判，连续超限的时段算一段，**中间只要有记录回到范围内就断开**；每段的时长按该段相邻记录的实际时刻差累加。
3. **累计超限**：一个批次从入库到当前，所有超限段的时长之和；**跨月不重置**，按批次周期累计。
4. **断链**：相邻两条记录的时刻差超过 `chainGapMinutes`（默认 15 分钟）算一处断链，缺口时长按实际时刻差算。
5. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与计算的记录条数）；**不是把温度取平均**。
6. **放行判定四条**：单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）、累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟）、全程没有断链、**参与判定的探头都在校准有效期内**。四条同时满足才算满足放行条件；**没有任何温度记录的批次不能放行**。
7. **人工更正留痕**：自动采集的读数有偏差时走「更正」，不是直接改数——每次更正都新增一条更正台账，登记**改前值、改后值、该时刻的原始值、更正人、更正时刻与依据**，并带递增序号；原始温度记录保留不动、可查。同一探头同一时刻可以被**反复更正**（包括改了又改回去），每次都留痕，按序号排出完整历史；判定与各类统计一律按**该时刻最新一次更正后的值（最终采用值）**实时重算。历史上「同一探头同一时刻既有自动记录又有手工记录」的覆盖，系统启动时自动补登为一条更正（依据中标注为存量补登）。页面上同一时刻的**原始值、更正后值与最终采用值并排显示**。
8. **更正占比与提醒**：更正占比＝该探头（或批次）**被更正过的采集时刻数 ÷ 采集时刻总数**（同一时刻反复更正只算一个被更正时刻；更正条数则按动作全计）。探头占比达到 `correctionWarnPct`（默认 10%，更正台账页面上可直接改，也可在设置里存为默认）时，在更正台账里单独列出高亮提醒。
9. **更正后的判定重算**：更正登记后，受影响批次的放行四项、MKT、最长/累计超限、断链数立即按最终采用值重算，并给出改前/改后逐项对照（含判定是否翻转）；已经放行/拒收的历史放行单数字不动，批次清单与判定显示的是重算后的当前值。
10. **删除级联**：删除一条温度记录时，若同一探头同一时刻还有别的记录，更正台账保留；该时刻记录全部删除后，挂在该时刻上的更正才一并清除；删除批次随批次清除其更正。停用探头名下的记录不参与判定。
11. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改 / 删除 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含记录、超限段、断链、放行单）/ 修改 / 删除 |
| GET | /api/batches/:id/release-check | 这个批次的放行判定 |
| POST | /api/batches/:id/decision | 放行或者拒收，body `{decision, decider, decidedAt, basis, remark}` |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、corrected、from、to；每条返回原始值 rawTemperatureC/originalTemperatureC、最终采用值 adoptedTemperatureC、更正次数等）/ 新增 |
| DELETE | /api/records/:id | 删除一条记录（同探头同时刻记录全删光时，其更正一并清除） |
| POST | /api/records/:id/corrections | 对一条读数登记人工更正，body `{toValueC, corrector, correctedAt, basis, remark}`；返回更正台账条目与受影响批次判定的改前/改后对照 |
| GET | /api/corrections | 更正流水（支持 batchId、probeId、recordId、corrector、from、to） |
| GET | /api/corrections/summary | 更正汇总：按探头/批次的更正条数、被更正时刻数、更正占比，达到 threshold（默认取设置 `correctionWarnPct`，可用 query 覆盖）的探头在 warnedProbes 里单独列出 |
| GET | /api/corrections/repeated | 同一探头同一时刻被更正不止一次的时刻及其完整历史（支持 probeId、batchId） |
| GET | /api/probes/:id/correction-history?at=... | 某探头某一时刻按序号排列的更正历史与最终采用值 |
| GET | /api/releases | 放行台账（支持 batchId、decision） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
